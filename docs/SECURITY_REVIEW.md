# Independent security review — 2026-09-19

Reviewed baseline commit `4f50a0e` and the coordinator's subsequent working-tree fixes. The reviewer did not author the application permission policy. This was a bounded code and PostgreSQL regression review, not a penetration-test certification or authorization for production launch. Application implementation remained coordinator-owned; the reviewer owns only this report and `tests/test_security_races.py`.

Scope: R16 consent/withdrawal, R17 reviewer authority, R18 optional model egress, R22 operational security, and the new pilot identity, password-reset, contact, monitoring and benchmark paths. No real private data or live external-model requests were used. Test database `test_philanthra_security_review` is separate from the demo and other agents' test databases.

## Findings and fixes

| Finding | Original severity | Reproduction and impact | Fix/recheck |
| --- | --- | --- | --- |
| SEC-01: contributors could provision their own trusted reviewer | High; release blocker | `accounts/views.py`, `MembersView.patch` and `InvitationsView.post` accepted `reviewer` from an ordinary workspace owner. The owner could invite and redeem a second controlled account, submit an identity/card artifact to that account, and approve it through the normal reviewer API. Another path gave an existing contributor a reviewer membership in a separate workspace; `reviewer_scope_allowed` did not exclude that user from approving edits in the contributor workspace. | SEC-02: queued PATCH requests could write after withdrawal committed | High; release blocker | `core/views.py`, portfolio/card/program/import PATCH handlers checked availability before waiting for a source lock. A second transaction could withdraw the source while the edit waited. The edit then reloaded the record but checked only its ordinary revision, restored draft/private fields, and returned a private serializer response. Withdrawal changes the source revision, so an unchanged artifact revision was insufficient. | Coordinator rechecks current artifact/source authorization immediately after acquiring locks, before mutation. Independent `tests/test_security_races.py` holds the real source lock, observes the PATCH backend waiting in PostgreSQL, commits withdrawal first, and checks a denied response plus unchanged private fields/revisions and no revived queued job. | SEC-03: identity linkage outlived its approved review state | High for identity verification; release blocker | `pilot/services.py`, `after_review` originally returned for every non-approved decision. Five independent identity cases passed: pending review, rejection, direct reviewer withdrawal, grant revocation and underlying source edit. |
| SEC-04: production boot accepted development host defaults | Medium; production blocker | Importing settings with production mode, a supplied strong-length secret, a dedicated database URL, HTTPS CSRF origin and storage acknowledgment succeeded with `ALLOWED_HOSTS` omitted. ## Controls checked

- Source grants match an explicit supported purpose, audience/recipient, cause, geography and expiry. Derived artifacts require every dependency's source/grant revision to remain current. Reviewer delegation covers the artifact owner's own sources while separately requiring authorization for third-party sources. There is no superuser/staff shortcut in source visibility.
- Recommendation execution locks source inputs and fences lease/source revisions. Both worker matching and the read path require explicit benchmarking permission. Alert records carry the private target source and revision; target withdrawal denies alerts as well as peer-source withdrawal.
- Fixed pooled releases suppress the entire output when a contributing binary cell/complement or independent-organization threshold fails. Suppressed outputs omit rates, totals, source citations and attribution metadata; approval rejects suppressed/incompatible payloads. Existing adversarial tests check JSON/CSV/guessed IDs, graph and citations rather than relying solely on hidden UI controls.
- Identity proof access requires ownership or current assigned-review scope and writes an audit event. Initial claim approval locks the organization/workspace and refuses takeover of an already assigned identity. See SEC-03 for the additional invalidation issue found in this review.
- Password reset uses Django tokens, a locked account for redemption, generic request responses, explicit anonymous CSRF protection, and a fail-closed production delivery boundary. Contact disclosure requires an accepted request owned by the recipient workspace and currently enabled contact consent. Disabled contact consent is checked on each read.
- Financial benchmarking uses compatible public financial records and does not silently add private outcome cells. Monitoring re-derives current permitted evidence after locking sources and omits revoked prior titles/numerical contents from newly generated alerts.
- Uploads are bounded by type/size/schema and tenant ownership. XLSX formulas, active relationships, unsafe archives and sensitive-column examples are rejected; report extraction is isolated and quarantined. Raw uploads are not publicly served. A regex does not prove de-identification; manual governance remains necessary.
- Public-source fetching uses a fixed allowlist, verifies public DNS answers, connects to the checked address while verifying the original TLS hostname, rejects redirects and bounds response size/time. Optional model requests use a fixed endpoint and are disabled by default.
- The explanation boundary locks sources, reauthorizes, requires current external-processing grants and only allows the model to select already authorized reviewed claim IDs and predefined questions. It cannot author authoritative amounts, new citations or factual prose. Provider tests assert no egress for absent permission, inactive/unreviewed evidence and the disabled provider; malformed output, fabricated selections and timeout fall back without logging private prompts.
- Session login has explicit CSRF protection; authenticated unsafe endpoints use framework session authentication. Default logs avoid full prompts/upload rows and worker errors persist exception type rather than exception contents. These checks do not establish protection for every future log statement.

## Limits and remaining release work

Do not treat the earlier 167-test integration result or this bounded review as proof that every production path is secure. All five confirmed findings above have fixes and passing focused regressions in the reviewed working tree. The final integrated test gate must still complete after final source changes. Docker/production proxy behavior, real mail delivery, production encryption/backup operations, external model behavior and human reviewer qualification were not exercised here. The reviewer previously implemented local runtime infrastructure, so this review does not claim independent container/runtime implementation review. Privacy rules still require authorized real pilot input and operational governance before a public launch.

Coordinator integration note: the final combined gate completed after this bounded review: 192 backend, 13 component and 14 browser tests passed, with build/check/smoke gates. See BUILD_STATUS.md for exact coverage and environment limits; this does not expand the independent review scope.
